# 隐私与数据说明

> 本文用于核对代码、微信《用户隐私保护指引》和小程序内隐私政策是否一致，不替代
> 法律意见。基线日期：2026-08-19。

## 1. 当前处理的数据

| 数据 | 来源 | 用途 | 主要存储 |
| --- | --- | --- | --- |
| 微信 `openid` | 微信运行环境 | 识别账号、校验数据权限 | `users` 及业务记录 |
| 头像、昵称 | 用户主动选择/填写 | 登录、个人主页、作品和互动展示 | `users`；头像在 COS |
| 性别、年龄、简介、北京区县 | 用户主动填写 | 个人资料和社区地区展示 | `users` |
| 手机号 | 用户选择手机号登录或主动填写时 | 登录/绑定及必要联系 | `users`，接口对外裁剪 |
| 社区作品、评论、回复、点赞和关注 | 用户主动操作 | 社区展示和互动 | 社区相关集合 |
| 行程、申请留言、成员和旅行记录 | 用户主动操作 | 行程组织、展示和通知 | 行程相关集合 |
| 图片 | 用户从相册选择或拍摄 | 头像、作品、评论、封面、记录和举报展示 | 新数据主要在 COS |
| 用户主动选择的位置 | `wx.chooseLocation` | 标注社区动态、行程目的地或旅行记录地点 | 对应业务记录 |
| 举报与反馈 | 用户主动提交 | 内容治理、问题处理 | `reports`、`feedbacks` |
| 操作与错误信息 | 程序运行产生 | 故障排查、统计和安全 | 日志和 `user_stats` |

## 2. 位置说明

代码中没有调用 `wx.getLocation`，不会进入页面后自动读取当前手机位置，也不会后台
持续定位。

当前调用 `wx.chooseLocation` 的场景包括：

- 发布社区动态时主动选择位置；
- 发布行程时主动选择目的地定位；
- 发布旅行记录时主动选择打卡地点。

编辑资料中的“地区”是用户从北京市区县列表中手动选择的资料字段，不是手机定位；
但它仍属于用户主动提供的地区信息，应在隐私政策的个人资料部分说明。

微信隐私保护指引中“位置信息用途”建议填写：

> 用于在你主动发布社区动态、行程或旅行记录时，选择、标注并展示地点信息。

当前 `app.json` 的权限描述“用于记录旅途打卡位置”范围偏窄，提交新版本时应与上述
实际用途保持一致。

## 3. 图片和第三方服务

- 新头像、社区作品、评论、行程封面和旅行记录图片上传到腾讯云 COS。
- 当前 Bucket 为公有读、私有写，获得完整 URL 的人可能访问图片。
- 图片和文字会调用微信内容安全能力；风险建议可能进入人工复核或触发评论隐藏。
- 举报图片同样属于用户主动上传内容，应在隐私说明中覆盖。
- 历史微信云存储图片可能继续通过临时 URL 展示。

在隐私政策中应说明使用腾讯云存储和微信内容安全能力的目的，但不要公开 SecretId、
SecretKey、内部管理员信息或其他安全配置。

## 4. 展示和共享边界

- 用户主动发布的昵称、头像、地区、动态、行程、评论和旅行记录会向其他用户展示。
- 手机号、登录凭证、密码字段和内部审核信息不应由公开用户接口返回。
- 后台管理为了运营和审核可以通过云函数读取必要数据，并受管理员身份校验。
- 举报内容属于内部治理数据，不通知被举报者，也不公开展示。

## 5. 用户控制

当前产品提供编辑资料、删除作品/评论/旅行记录和反馈入口。隐私政策还应明确：

- 如何查询、更正和删除个人信息；
- 如何撤回授权；
- 如何申请注销账号；
- 如何投诉、举报和联系运营者；
- 删除后因安全、争议处理或法律要求需要保留的数据及期限。

若页面尚未提供独立注销按钮，应确保“用户反馈”确实能接收并处理注销请求，不能只在
协议中承诺但无人处理。

## 6. 每次新增功能的核对项

1. 是否新增微信隐私接口或系统权限。
2. 是否新增收集的数据、用途、第三方服务或公开展示范围。
3. 是否需要用户主动同意，拒绝后能否继续使用非相关功能。
4. 数据是否经过云函数权限校验，是否含不必要的敏感字段。
5. 删除业务数据时，COS 对象、审核记录和缓存如何处理。
6. 同步更新微信后台隐私指引、小程序内隐私政策和本文档。

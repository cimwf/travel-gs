# 当前架构与业务规则

> 基线日期：2026-08-19。本文描述当前代码已经采用的规则，不包含仅存在于设计稿中的
> 规划功能。

## 1. 系统边界

```text
微信小程序 miniprogram/
        │ wx.cloud.callFunction
        ▼
统一云函数 cloudfunctions/api
        ├── 微信云数据库
        ├── 腾讯云 COS（STS 限定对象上传）
        └── 微信内容安全接口

图片审核事件 ──► community-media-check-result

后台管理 ../travel-be-gs ──► 同一个 api 云函数 ──► 同一套数据
```

云函数是后端，后台管理项目只是管理端前端。业务集合统一设置为小程序客户端不可直接
读写；小程序和管理端都必须通过 `api` 云函数访问。

## 2. 登录与用户

- 微信身份以 `openid` 为主，一个微信号只对应一个小程序账号。
- 新用户通过微信 `chooseAvatar` 和昵称能力完善资料；头像上传到 COS。
- 编辑资料支持头像、昵称、性别、年龄、北京区县和简介。
- 地区是用户手动选择的资料字段，不是自动读取的手机定位。
- 对外用户资料接口会裁剪敏感字段，不返回密码等认证信息。
- 关注关系保存在 `user_follows`，关注/取消关注同步维护统计并产生或撤销通知。

## 3. 社区

### 列表和发布

- 社区是默认首页，列表默认按 `createdAt + _id` 倒序，每页 10 条。
- 支持“全部/关注”和北京区县筛选；有地区时在发布时间后展示区县。
- 动态支持文字、多图、主动选择的位置、点赞、评论、回复、分享、删除和举报。
- 点击内容区域进入详情，点击头像进入个人主页。
- 官方账号也写入 `users`，官方动态和普通动态统一写入 `community_posts`。

### 审核状态

社区采用“先发布、后审核”：

- 创建时 `status=active`、`reviewStatus=approved`，内容立即可见。
- 文字和图片的机器结果保存在 `machineSuggest`。
- `pass`：保持公开，不要求人工处理。
- `review`：保持公开，`adminReviewStatus=pending`，后台显示待复核。
- `risky`：保持公开，`adminReviewStatus=pending`，后台显示待人工审核。
- 管理员通过：保持 `reviewStatus=approved`。
- 管理员拒绝：改为 `reviewStatus=rejected`，公共列表隐藏，作者仍可在自己的作品中查看。
- 删除作品使用 `status=deleted`，同时尝试删除关联 COS 图片；失败任务写入清理集合。

`review` 和 `risky` 是机器风险建议，不等于最终违规结论。

### 评论

- 主评论和回复均支持纯文字或最多 3 张图片。
- 回复平铺在所属主评论下，显示“A 回复 B：内容”。
- 评论作者可以删除自己的评论；作品作者可以删除自己作品下的任意评论。
- 评论文字发布前必须通过 `msgSecCheck`；图片评论发布后立即展示并异步审核，图片返回
  `risky` 时回调会自动把该评论改为拒绝并回减评论数，`pass/review` 保持展示。
- 评论地区使用评论时保存的用户地区快照，没有地区则不展示。

## 4. 行程

- 公共行程列表每页 10 条，服务端按北京时间将数据分成“今天及以后”和“往期”两个
  稳定游标阶段，先展示当前/未来行程，再展示往期行程；整张卡片可进入详情。
- 往期展示由后台 `system_config/trip_list_visibility` 按 `dev/test/prod` 独立控制，默认
  关闭；开启后往期卡片统一显示“已结束”，可查看、评论和分享，但前后端都禁止申请加入。
- 往期详情隐藏编辑、开始出发、发布日志、更换封面和日志授权入口；云函数同时拒绝行程
  编辑/状态修改、开始或结束行程、日志上传会话与日志创建，不能通过直接调用接口绕过。
- “我的行程”和个人主页行程不受公共列表的往期展示开关影响。
- 往期分页采用客户端能力标识；未携带新分页标识的旧版小程序仍只读取当前/未来行程，
  避免云函数先发布时破坏旧版游标。
- 发布内容包含日期、集合时间、集合地点、目的地定位、人数、价格、说明和封面等。
- 创建时默认 `reviewStatus=approved`，立即展示；后台可以改为 `rejected`。
- 访客可以申请加入并填写可选留言；发起人在消息中心直接同意或拒绝。
- 申请通过后发送结果通知，拒绝不通知申请人。
- 发起人可管理成员和行程状态；访客与发起人均可分享行程。
- 行程详情固定显示“行程 / 旅途记录 / 评论”三个 Tab。

### 旅途记录

- 未出发也能查看空状态，但点击发布会提示出发后才能发布。
- 日志支持文字、COS 图片和主动选择的位置。
- 与社区相同，日志先公开；机器结果只决定是否进入后台复核，管理员拒绝才隐藏。
- 删除日志会局部刷新列表，并尝试清理对应 COS 对象。

### 行程评论

- 主评论和回复支持文字或最多 3 张图片。
- 评论作者可删除自己的内容；行程发起人可删除该行程下的评论。
- 评论文字发布前必须通过 `msgSecCheck`；图片评论先展示并异步审核，图片返回 `risky`
  时回调自动隐藏评论并回减数量，`pass/review` 保持展示。

## 5. 消息中心

`notifications` 是当前统一站内通知源，分为：

- `trip`：加入申请、处理结果、成员和行程变化。
- `interaction`：点赞、评论、回复和关注。
- `system`：后台人工审核结果等系统通知。

小程序启动及回到前台时检查未读数量；有未读消息时显示使用系统头像的全局横幅，点击
进入消息中心。当前不是实时长连接，也不是微信订阅消息。

详细事件和索引见 [消息中心通知规则](message-center-notification-spec.md)。

## 6. 举报与后台审核

- 举报入口位于社区列表、社区详情和旅行记录等内容的操作菜单。
- 举报记录包含类型、目标 ID、理由、说明和可选图片。
- 举报不会自动通知被举报人，也不会自动下架内容。
- 管理员在后台查看举报，打开对应作品判断；如违规，走已有审核接口将内容拒绝。
- 后台还包括社区审核、行程审核、旅行记录审核、官方账号与动态、用户反馈、景点、
  用户上传、图片资源和用户管理。

## 7. 图片与存储

新上传内容使用腾讯云 COS：

| 类型 | 默认目录 |
| --- | --- |
| 社区作品 | `miniapp/community/` |
| 社区评论 | `miniapp/community-comments/` |
| 行程日志、行程封面、头像等 | `miniapp/` 下按用途生成目录 |

上传流程为：前端请求上传会话 → 云函数签发只允许指定 Key 的短期 STS → 前端上传
COS → 业务接口使用 `headObject` 校验后入库。SecretId/SecretKey 只保存在云函数环境
变量。历史 `cloud://` 图片继续兼容，不强制迁移。

## 8. 数据环境隔离

三个运行版本共用一个云开发环境和数据库：

| 微信版本 | 写入 | 默认读取 |
| --- | --- | --- |
| `develop` | `dev` | `dev` |
| `trial` | `test` | `test` |
| `release` | `prod` | `prod` |

- 没有 `dataEnv` 的历史数据仅视为 `dev`。
- 当前主要隔离行程列表、个人主页行程和社区内容。
- 若开发阶段临时需要跨环境读取，只修改 `miniprogram/utils/env.js` 的 `readEnvs`，
  不通过数据库配置动态切换。
- 官方动态固定先写 `dev`；后台点击“发布”时改为 `prod`，并将 `createdAt` 更新为
  实际发布时间。

## 9. 已知运维事项

- COS 删除失败会写清理任务，但仍需建立定时执行器或人工巡检。
- 上传后放弃发布可能留下过期草稿对象，需要定期清理。
- 图片审核回调依赖云开发消息推送规则，部署云函数不等于规则已经启用。
- 本地单元测试使用 mock，正式数据权限、索引、域名和回调必须真机验证。
